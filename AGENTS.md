# AGENTS.md

## Назначение

Этот файл предназначен для ИИ-агентов и разработчиков, работающих с проектом Family Archive.

Перед любыми изменениями обязательно прочитать:

- `docs/PROJECT_CONTEXT.md`
- `docs/DECISIONS.md`

Family Archive — не просто генеалогическое дерево. Это self-hosted семейный архив для долгосрочного хранения семейной истории, фотографий, документов, событий, биографий и родственных связей.

## Основные приоритеты

Приоритеты проекта расположены в следующем порядке:

1. Целостность и сохранность данных.
2. Корректность родственных связей.
3. Стабильность работающих функций.
4. Простота использования.
5. Внешний вид и производительность.

Нельзя улучшать раскладку или внешний вид ценой потери связей, данных или рабочих сценариев.

## Текущий стек

- Frontend: Vite.
- Отображение дерева: Family Chart.
- Backend: PocketBase.
- Целевая платформа: Raspberry Pi 5, Linux ARM64.
- Сервис: systemd.
- CLI проекта: `family-archive`.
- Текущий unit-файл может называться `family-tree.service`; это известная несогласованность.
- Развёртывание: сборка frontend и копирование в `pb_public`.

## Правила работы

- Предпочитать небольшие изолированные изменения.
- Не выполнять крупный рефакторинг без прямой необходимости.
- Не менять архитектуру базы данных, модель связей, роли, приглашения или установщик без отдельного согласования.
- Не удалять существующую функциональность ради упрощения задачи.
- Не считать визуально успешную сборку доказательством корректности логики.
- Не делать автоматических изменений родственных связей без явного подтверждения пользователя.
- Не полагаться только на память чата или предыдущего агента. Источником истины являются код, Git и документы проекта.
- При расхождении между кодом и документацией сначала зафиксировать расхождение, затем выяснить, что является актуальным решением.
- Не добавлять новые зависимости без обоснования.
- Не менять публичные команды CLI и структуру release без учёта обратной совместимости.

## Работа с Git

- Ветка `main` должна оставаться стабильной и готовой к развёртыванию.
- Экспериментальные изменения выполнять только в отдельных ветках.
- Не объединять экспериментальную ветку с `main`, пока не выполнены проверки и пользователь явно не подтвердил результат.
- Перед началом работы проверить текущую ветку и чистоту рабочего дерева.
- Перед опасными изменениями создать понятную точку возврата.
- Не выполнять `git reset --hard`, удаление веток, принудительный push и другие разрушительные команды без прямого подтверждения.
- Известная неудачная ветка: `experiment/full-tree-layout`, commit `af8721e`. Не сливать её в `main`.
- Последняя подтверждённая стабильная версия: `v0.3.2`, commit `f3d37de`.

## Обязательные проверки для изменений дерева

После любых изменений, затрагивающих данные людей, связи или отображение дерева, проверить:

- загрузку существующего архива;
- создание нового человека;
- редактирование человека;
- добавление матери;
- добавление отца;
- добавление ребёнка;
- добавление супруга или супруги;
- отображение родителей;
- отображение детей;
- отображение супругов;
- отображение братьев и сестёр;
- наличие и корректность линий родства;
- отсутствие дубликатов людей;
- сохранение после перезагрузки страницы;
- мобильное отображение;
- desktop-отображение;
- работу форм на iOS;
- отсутствие ошибок JavaScript в консоли;
- сборку production-версии.

Минимальная техническая проверка:

```bash
npm ci
npm run build
```

Использовать команды, которые реально существуют в текущем `package.json`. Не придумывать тесты или скрипты, которых в проекте нет.

## Особые правила дерева

- Family Chart используется как движок отображения, а не как источник продуктовой логики.
- Встроенный редактор Family Chart должен быть заменён собственным интерфейсом Family Archive.
- Изменения transient tree и полного дерева считаются рискованными.
- Нельзя считать задачу выполненной, если улучшилась раскладка, но исчезли линии или родственники.
- В полном дереве нужно учитывать не только центрального человека, но и супругов отображаемых родственников.
- Если движок не поддерживает нужное поведение публичным API, не использовать хрупкие внутренние обходы без отдельного обсуждения.

## Пользователи и приглашения

- Роль «Член семьи» должна быть связана с конкретной карточкой живого человека в дереве.
- Один пользователь не должен незаметно привязываться к нескольким карточкам.
- В карточке живого родственника предусматривается действие «Пригласить родственника».
- Персональная ссылка приглашения связывает зарегистрировавшегося пользователя с указанной карточкой.
- Одна карточка имеет не более одной активной ссылки.
- Ссылка становится недействительной после использования или отзыва.
- Гостевой просмотр без авторизации допускает только дерево, без доступа к карточкам людей и личным данным.

## UX

- На desktop не использовать узкую боковую панель там, где нужен полноценный центральный диалог.
- Формы должны быть собственными и понятными, без дублирующих полей.
- Не использовать бессмысленные placeholders вместо подписей.
- Строки родственников должны быть кликабельными.
- Длинные имена на мобильных устройствах должны переноситься, а не обрезать интерфейс.
- Умное заполнение и предложения связей допустимы только как подсказки.
- При добавлении второго родителя можно предложить связать родителей как супругов, но решение всегда подтверждает пользователь.
- Снятие предложенной связи не должно приводить к созданию неправильной родственной модели.

## Установщик и эксплуатация

При изменениях установщика учитывать:

- чистую установку;
- обновление;
- резервное копирование;
- восстановление;
- rollback;
- миграции PocketBase;
- systemd;
- диагностику `doctor`;
- ARM64;
- сохранение пользовательских данных;
- повторный запуск после частично завершённой установки.

Нельзя считать обновление безопасным без описанного пути отката.
