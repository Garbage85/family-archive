# Вычисляемое родство

Степень родства — производное представление текущей структуры дерева относительно выбранного
центрального человека. В `trees.data` сохраняются только исходные `parents`, `children`, `spouses`
и сведения человека; вычисленные термины и пути в данные дерева не записываются.

## Архитектура

- `kinship-engine.js` нормализует одно- и двусторонние связи в ориентированные наборы родителей и
  детей и отдельный неориентированный набор супругов. Ссылки на отсутствующих людей и повреждённые
  циклы дают предупреждения, но не останавливают обход.
- `kinship-formatter-ru.js` переводит структурный результат (`a`, `b`, разницу поколений, пол и тип)
  в русский термин. DOM и Family Chart в форматтере не используются.
- `kinship-state.js` выбирает безопасный `centerPersonId`, сохраняет только ID в `localStorage` и
  мемоизирует индекс по identity/revision дерева и центру.
- Family Chart получает выбранный ID через поддерживаемый API `updateMainId(centerId)` и затем
  заново выполняет `updateTree({ tree_position: 'fit' })`. Обычный клик по карточке root не меняет.

Для кровного родства движок строит и кеширует кратчайшие пути от человека к его предкам. Прямой
предок или потомок имеет приоритет. Для боковой ветви пересекаются карты предков центра и цели;
кандидаты сортируются по `a + b`, затем по разнице поколений и стабильному ID. Два общих предка,
которые задают одну и ту же семантическую ветвь (например, оба родителя брата), объединяются.
Содержательно разные ветви остаются альтернативами. Spouse-рёбра не участвуют в кровном обходе;
сейчас распознаётся только непосредственный супруг центра.

## Ограничения первой версии

- тип родителя пока не различает biological, adoptive, step и guardian;
- родные и неполнородные братья и сёстры называются одинаково;
- сложное родство через брак не именуется;
- термины вычисляются только из `parents`, `children`, `spouses` и `gender`;
- подписи являются производным представлением, а не сохраняемыми фактами;
- движок сохраняет до трёх альтернатив, а окно показывает основной и не более двух дополнительных
  путей (до трёх цепочек всего).

Результат движка уже содержит `kind` и изолированные типы рёбер, поэтому будущие `affinal`,
`adoptive` и `guardian` можно добавить отдельными стратегиями, не меняя кровный обход.
