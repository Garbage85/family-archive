# База данных

## Общие сведения

Family Archive использует SQLite через PocketBase. Схема создаётся миграциями из
`pb_migrations`, а runtime-данные находятся в исключённом из Git каталоге `pb_data`.

Foundation 0.3 не изменяет миграции, коллекции, API-правила и формат `trees.data`.
Источником точной схемы остаётся
`pb_migrations/1785456000_initial_family_tree.js`.

## Коллекции

### `users`

Auth-коллекция пользователей сайта. Дополнительные поля:

- `name` — отображаемое имя;
- `role` — одно из `viewer`, `member`, `admin`.

Пользователь может просматривать собственную запись, администратор — список
пользователей. Создание и изменение выполняются административным контуром.

### `trees`

- `name` — название дерева;
- `data` — полный JSON-снимок дерева, максимум 10 MiB;
- `revision` — целочисленная версия снимка;
- `updated_by` — последний редактор.

Читать дерево может любой авторизованный пользователь. Изменять его напрямую может
только администратор.

### `proposals`

- `tree` — изменяемое дерево;
- `author` — автор предложения;
- `base_revision` — версия дерева, от которой сделано предложение;
- `data` — предлагаемый полный JSON-снимок;
- `comment` — комментарий автора;
- `status` — `pending`, `approved` или `rejected`;
- `reviewed_by`, `reviewed_at`, `review_note` — результат модерации.

Участник создаёт предложение от своего имени. Решение принимает администратор.

### `media`

- `person_id` — идентификатор человека внутри `trees.data`;
- `author` — загрузивший пользователь;
- `file` — JPEG, PNG или WebP до 10 MiB.

PocketBase создаёт thumbnail `320x320`. В текущей схеме `person_id` является строкой,
а не relation field, поскольку люди ещё хранятся внутри JSON.

## Формат `trees.data`

```json
[
  {
    "id": "person-id",
    "data": {
      "gender": "M",
      "first_name": "Имя",
      "last_name": "Фамилия",
      "middle_name": "Отчество",
      "birth_date": "1985-12-08",
      "death_date": "",
      "birth_place": "",
      "occupation": "",
      "notes": "",
      "avatar": ""
    },
    "rels": {
      "parents": [],
      "spouses": [],
      "children": []
    }
  }
]
```

`parents`, `spouses` и `children` содержат ID других элементов того же массива.
Этот контракт сохраняется без изменений на всём протяжении релиза 0.3.

## Резервное копирование

`scripts/backup-server.sh` кратко останавливает сервис, делает согласованный снимок
`shared/pb_data`, а затем создаёт и проверяет архив с SHA-256. Исходники,
`node_modules` и собранный frontend в backup не включаются.

`scripts/rollback-server.sh` восстанавливает данные только с явной опцией
`--restore-data`, предварительно проверяет пути и типы файлов архива и создаёт
аварийный backup текущего состояния. Подробности приведены в
[`BACKUP_AND_ROLLBACK.md`](BACKUP_AND_ROLLBACK.md).

Перед изменением схемы в последующих релизах обязательны backup и проверка миграции
на копии реальных данных.
